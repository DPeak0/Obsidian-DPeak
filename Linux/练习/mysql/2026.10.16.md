### 任务 1：规范化数据库与表结构设计 (DDL)

**企业需求**：为了防止未来出现生僻字和 Emoji 表情乱码，需按照最新规范创建电商数据库及核心业务表。

1. 创建一个名为 `shop_db` 的数据库，必须显式指定其字符集为 MySQL 8.0 推荐的 `utf8mb4`。
```mysql
mysql> create database shop_db default character set utf8mb4;
Query OK, 1 row affected (0.00 sec)
```
![](https://oss.bwihz.cn/PicGo/20261018182209416.png)

2. 切换到 `shop_db` 数据库下，创建两张表：
    1. **商品表 (****`goods`****)**：
        - `id`：主键，无符号整数，自动自增。
        - `name`：商品名称，变长字符串（长度50），不能为空。
        - `stock`：库存数量，无符号整数，不能为空。
		
		```mysql
		mysql> use shop_db;
		Database changed
		mysql> CREATE TABLE goods (
		    -> id int UNSIGNED AUTO_INCREMENT PRIMARY KEY,
		    -> name VARCHAR(50) NOT NULL,
		    -> stock int UNSIGNED NOT NULL
		    -> );
		Query OK, 0 rows affected (0.01 sec)
		```
		![](https://oss.bwihz.cn/PicGo/20261018185613815.png)

    2. **订单表 (****`orders`****)**：
        - `id`：主键，无符号整数，自动自增。
        - `order_no`：订单流水号，变长字符串（长度50），不能为空。
        - `goods_id`：关联的商品ID，无符号整数，不能为空。
        - `buy_num`：购买数量，无符号整数，不能为空。
		```mysql
		mysql> CREATE TABLE orders (
			-> id int UNSIGNED AUTO_INCREMENT PRIMARY KEY,
			-> order_no VARCHAR(50) NOT NULL,
			-> goods_id int UNSIGNED NOT NULL,
			-> buy_num int UNSIGNED NOT NULL
			-> );
		Query OK, 0 rows affected (0.02 sec)
		```

### 任务 3：业务逻辑自动化部署 (Trigger)

**企业需求**：为了防止应用层代码在网络抖动时导致订单和库存数据不一致，要求在数据库底层实现“下单自动扣减库存”的逻辑。

1. 创建一个名为 `tr_after_insert_order` 的触发器。
    
2. 规则：当在 `orders` 表中成功插入一条新订单记录后（AFTER INSERT），自动更新 `goods` 表，将对应商品的库存扣减掉本次订单的购买数量。
    
3. 测试触发器：向 `orders` 表中再插入一条新订单（订单号: 'SN1003', 商品ID: 1, 购买数量: 3），然后查询 `goods` 表，截图证明商品1的库存已正确减少。

4. 将 `dev_role` 角色分配给 `coder` 用户。

### 任务 5：全量逻辑备份 (Backup)

**企业需求**：在业务上线前，需要对初始化好的整个数据库进行一致性全量备份。

1. 退回到 Linux 命令行界面。
    
2. 创建备份存放目录 `/backup/mysql/`。
    
3. 使用 `mysqldump` 工具将 `shop_db` 数据库全量导出到 `/backup/mysql/shop_db_bak.sql` 文件中。要求：必须使用 `--single-transaction` 参数保证备份期间不锁表（模拟企业不影响业务的备份要求）。
