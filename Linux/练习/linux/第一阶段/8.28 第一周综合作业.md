
#  Linux 高级运维实战：多项目环境部署与权限体系构建（终极版）

## 作业背景

你是一家快速发展的互联网公司的系统管理员。公司需要在同一台服务器上为两个独立的项目 `cloud_backend` 和 `ai_engine` 搭建运行环境。这两个项目由不同的团队负责，对文件权限和用户管理有严格且复杂的要求。你需要在 4 小时内，完成从零开始的环境初始化、用户体系构建、精细化权限控制、提权策略配置以及自动化日志管理。

------

## 阶段一：用户与组体系构建（7题）

1. **创建核心用户组**：使用 `groupadd` 命令创建三个用户组：`backend_dev`（后端开发团队）、`ai_research`（人工智能研发团队）、`sec_audit`（安全审计部门）。
2. **创建项目用户**：创建用户 `frank` 和 `grace`，将他们的私有组设为 `backend_dev`，附加组设为 `sec_audit`；创建用户 `henry` 和 `ivy`，将他们的私有组设为 `ai_research`，附加组设为 `sec_audit`。
3. **设置密码**：使用 `passwd` 命令为以上四位用户设置登录密码，密码设置为1。
4. **创建服务账户**：创建系统用户 `backend_svc` 和 `ai_svc`，均不允许登录系统（shell 设置为 `/sbin/nologin`），分别用于运行后端服务和 AI 引擎服务。
5. **修改用户信息**：使用 `usermod` 命令将用户 `ivy` 的描述信息修改为 "AI Researcher - Senior"。
6. **锁定与解锁用户**：使用 `usermod` 命令锁定用户 `grace` 的账户，验证她无法登录系统（可尝试使用 `su` 命令切换），之后再解锁该账户。
7. **管理组成员**：创建一个名为 `temp_group` 的组，使用 `groupmems` 命令将 `frank` 和 `henry` 添加为该组的成员，再使用 `groupmems` 列出该组成员进行确认；最后使用 `id` 命令分别检查 `frank` 和 `henry` 的用户信息，确认其主要组和附加组配置正确。

---

```bash

[root@dpeak ~]# groupadd backend_dev
[root@dpeak ~]# groupadd ai_research
[root@dpeak ~]# groupadd sec_audit

[root@dpeak ~]# useradd -g backend_dev -G sec_audit frank
[root@dpeak ~]# useradd -g backend_dev -G sec_audit grace
[root@dpeak ~]# useradd -g ai_research -G sec_audit henry
```

## 阶段二：项目目录结构与基础权限（6题）

1. **创建项目根目录**：在 `/opt` 下创建 `cloud_backend` 和 `ai_engine` 两个目录。
2. **配置后端项目归属与权限**：将 `/opt/cloud_backend` 的拥有组修改为 `backend_dev`，并设置权限，使 `backend_dev` 组成员拥有读、写、执行权限，其他用户无任何权限。
3. **设置 SGID**：为 `/opt/cloud_backend` 目录设置 SGID 特殊权限，确保组内成员在该目录下新创建的文件自动继承 `backend_dev` 组。
4. **设置 SBIT**：为 `/opt/cloud_backend` 目录设置 SBIT 特殊权限，防止组内成员误删他人的文件。
5. **配置 AI 项目目录**：将 `/opt/ai_engine` 的拥有组修改为 `ai_research`，设置权限使 `ai_research` 组成员拥有读、写、执行权限，其他用户无任何权限，并同样为该目录设置 SGID 和 SBIT 特殊权限。
6. **数字模式练习**：在 `/opt/cloud_backend` 目录下创建文件 `config.ini`，使用 `chmod` 的数字模式将其权限设置为：拥有人可读写、拥有组只读、其他人无权限；然后以 `backend_dev` 组成员身份在 `/opt/cloud_backend` 目录下再创建一个新文件，使用 `ls -l` 验证新文件的拥有组是否自动变为了 `backend_dev`（验证 SGID 效果）。

## 阶段三：精细化权限控制（ACL）（5题）

1. **配置审计权限**：使用 `setfacl` 命令，赋予 `sec_audit` 组对 `/opt/cloud_backend` 和 `/opt/ai_engine` 两个目录的读和执行（`r-x`）ACL 权限。
2. **配置 ACL 默认权限**：为两个项目目录设置 ACL 默认权限，确保未来在这两个目录下新创建的任何文件或目录，`sec_audit` 组都自动拥有读和执行权限。
3. **配置跨组协作权限**：由于项目需要，使用 ACL 为 `frank` 用户（backend_dev 组）单独赋予 `/opt/ai_engine` 目录的 `r-x` 权限，并同时设置默认权限；然后切换到 `grace` 用户尝试进入 `/opt/ai_engine` 目录 *创建一个文件*，确认被拒绝；切换到 `frank` 用户，确认可以进入并列出文件；最后使用 `getfacl` 命令查看两个项目目录的 ACL 权限设置。
4. **目录 ACL 授权**：先创建目录 `/opt/cloud_backend/logs`，然后使用 ACL 赋予用户 `grace` 对该目录的读写执行（`rwx`）权限。
5. **ACL 清理**：因项目调整，`frank` 不再需要跨组访问权限。使用 `setfacl -x` 删除 `/opt/ai_engine` 目录上为 `frank` 用户设置的 ACL 权限，再使用 `setfacl -k` 删除该目录上的默认 ACL 权限，并使用 `getfacl` 验证清理结果。

## 阶段四：提权策略与特殊权限（4题）

1. **配置 Sudo 提权**：编辑 `/etc/sudoers` 文件，实现以下授权：
   - 授权 `frank` 用户可以使用 `root` 身份执行 `/usr/sbin/useradd` 和 `/usr/sbin/userdel` 命令。
   - 授权 `ai_research` 组的所有成员可以使用 `root` 身份执行所有命令。
   - 授权 `sec_audit` 组的所有成员可以使用 `root` 身份执行 `/usr/bin/cat` 命令。
2. **验证提权**：切换到 `frank` 用户，使用 `sudo` 命令创建一个名为 `backend_tester` 的新用户；切换到 `henry` 用户，使用 `sudo` 执行 `useradd ai_tester`，确认是否成功；再使用 `sudo -l` 命令列出 `henry` 当前拥有的所有提权权限。
3. **配置免密提权**：修改 `/etc/sudoers` 中 `frank` 的规则，让她在执行 `sudo` 命令时不需要输入自己的密码，然后切换到 `frank` 用户验证是否已无需输入密码。
4. **SUID 特殊权限**：为 `/usr/bin/touch` 命令文件赋予 SUID 权限；切换到 `grace` 用户，在 `/tmp` 目录下执行 `touch test_suid_file`，使用 `ls -l` 查看该文件的拥有者，确认其为 `root`；验证完成后，移除 `/usr/bin/touch` 命令的 SUID 权限。

## 阶段五：日志管理与 Vim 编辑器（6题）

1. **覆盖写入日志**：使用 `echo` 命令生成一条日志信息 "Backend service started on port 8080."，并使用输出重定向 `>` 将其覆盖写入到 `/opt/cloud_backend/logs/access.log` 文件中。

2. **追加写入日志**：使用输出重定向 `>>`，将 "Backend service running normally." 追加到 `/opt/cloud_backend/logs/access.log` 文件中；然后创建 `/opt/ai_engine/logs` 目录（如不存在），并将错误日志 "Database connection failed." 追加写入到 `/opt/ai_engine/logs/error.log` 文件中。

3. **错误输出重定向**：执行 `ls /nonexistent_dir` 命令，将正确的输出（如果有）重定向到 `output.txt`，将错误输出重定向到 `error.txt`；再执行一个错误的命令（例如 `lss`），并将所有的输出信息重定向到 `/dev/null`，确保屏幕上不显示任何输出。

4. **日志归档**：使用 `cp` 命令将 `/opt/cloud_backend/logs/access.log` 文件复制到 `/opt/cloud_backend/logs/access.log.bak`。

5. **Vim 编辑日志**：使用 `vim` 打开 `/opt/cloud_backend/logs/access.log` 文件，在文件末尾另起一行，添加你的姓名和当前日期（例如：`-- Logged by [你的姓名缩写，如xym] on 2026-08-28`），使用退出模式的 `set number` 显示行号，确认你添加的内容在最后一行，然后保存并退出。

6. **Vim 搜索、复制与替换**：使用 `vim` 打开 `/opt/cloud_backend/logs/access.log.bak` 文件，完成以下操作：
   - 使用 `/` 命令搜索关键字 `Backend`，并跳转到该关键字所在位置；
   - 在命令模式下复制文件的第一行（`yy`），并粘贴到文件末尾（`p`）；
   - 使用替换命令 `%s`，将文件中所有的 `8080` 替换为 `9090`；
   - 保存并退出。
   
   ---
