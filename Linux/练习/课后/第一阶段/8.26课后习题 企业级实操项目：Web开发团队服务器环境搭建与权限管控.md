# 8.26 企业级实操项目：Web开发团队服务器环境搭建与权限管控

## 项目背景

你刚刚入职公司，担任初级运维工程师。公司即将启动一个新的 Web 前端项目，你需要在一台全新的 Linux 服务器上，从零开始为“Web 开发团队”搭建基础运行环境。你的任务包括：规划团队账号体系、配置项目代码目录、设置团队协作与安全防护权限，以及为团队负责人配置合规的 sudo 提权策略。

请严格按照以下工单要求完成实操，并在每一步完成后进行验证。

------

## 第一阶段：团队账号体系规划与创建（工单 1-5）

### 1：创建开发团队主组

- **任务描述**：根据公司的组织架构规范，首先需要为 Web 开发团队创建一个专属的用户组。请创建一个名为 `web_dev` 的用户组，作为该团队所有开发人员的主组。
- **验证标准**：使用 `vim /etc/group` 命令，能够在文件中看到改组信息，确认该组已成功写入系统组文件。

---

```bash
[root@dpeak ~]# groupadd web_dev
```

### 2：创建前端开发人员账号

- **任务描述**：团队中有两名新入职的前端开发人员 `alice` 和 `bob`。请使用 `useradd` 命令为他们创建普通用户账号，并将他们的私有组直接指定为刚刚创建的 `web_dev` 组。
- **验证标准**：分别执行 `id alice` 和 `id bob`，确认他们的私有组是 `web_dev` 组。

---

```bash
[root@dpeak ~]# useradd -g web_dev alice
[root@dpeak ~]# useradd -g web_dev bob
[root@dpeak ~]# id alice
uid=3008(alice) gid=3009(web_dev) groups=3009(web_dev)
[root@dpeak ~]# id bob
uid=3009(bob) gid=3009(web_dev) groups=3009(web_dev)
```

---

### 3：创建 Web 服务专属运行账号

- **任务描述**：出于安全考虑，Web 服务不能以 root 身份运行。请创建一个名为 `www-data` 的系统用户，要求指定其 UID 为 `80`，家目录设置为 `/var/www`，并且必须禁止该用户通过 Shell 登录系统。
- **验证标准**：使用 `id www-data` 查看 UID，并查看 `/etc/passwd` 文件确认其登录 Shell 是否为 `/sbin/nologin`。

---

```bash

[root@dpeak ~]# useradd -r -u 80 -md /var/www -s /sbin/nologin www-data
[root@dpeak ~]# id www-data
uid=80(www-data) gid=80(www-data) groups=80(www-data)
[root@dpeak ~]# cat /etc/passwd | grep www-data
www-data:x:80:80::/var/www:/sbin/nologin
```

---

- **任务描述**：账号创建完成后，需要为开发人员设置初始登录密码，以便他们能够首次登录并修改密码。请为 `alice` 和 `bob` 两个用户设置初始密码，统一设为 `password123`。
- **验证标准**：使用 `su - alice` 切换用户，确认能够成功登录并进入家目录。

### 5：临时禁用离职人员账号

- **任务描述**：测试人员 `intern_user` 的实习期已满，为了安全起见，需要立即禁止该账号登录系统，但暂时保留其账号数据以备后续审计。请使用 `usermod` 命令将其登录 Shell 修改为禁止登录的状态。
- **验证标准**：使用 `su - intern_user` 确认用户是无法登陆的。

------

```bash
[root@dpeak ~]# useradd intern_user
[root@dpeak ~]# usermod -s /sbin/nologin intern_user
[root@dpeak ~]# su - intern_user
This account is currently not available.
```

## 第二阶段：项目目录与基础权限划分

### 6：创建项目代码根目录

- **任务描述**：在服务器上规划网站项目的存放位置。请使用命令创建一个目录 `/var/www/html` 作为网站项目的根目录。
- **验证标准**：使用 `ls -ld /var/www/html` 查看目录属性，确认目录已成功创建。

---

```bash
[root@dpeak ~]# mkdir /var/www/html
[root@dpeak ~]# ls -ld /var/www/html/
drwxr-xr-x. 2 root root 6 Aug 26 18:37 /var/www/html/
```

---

### 7：配置项目目录归属

- **任务描述**：为了明确责任划分，需要将项目根目录的所有权移交给 Web 服务账号和开发团队。请将 `/var/www/html` 目录的拥有人修改为 `www-data`，拥有组修改为 `web_dev`。
- **验证标准**：再次使用 `ls -ld /var/www/html` 确认已修改。

---

```bash
[root@dpeak ~]# chown www-data:web_dev /var/www/html/
[root@dpeak ~]# ls -ld /var/www/html/
drwxr-xr-x. 2 www-data web_dev 6 Aug 26 18:37 /var/www/html/
```

---

### 8：设置基础访问权限（数字模式）

- **任务描述**：根据安全基线要求，为 `/var/www/html` 目录设置基础权限：拥有人（`www-data`）拥有读、写、执行权限；拥有组（`web_dev`）拥有读、执行权限；其他人没有任何权限。请使用数字模式完成设置。
- **验证标准**：使用 `ls -ld /var/www/html` 查看权限字符串是否为 `drwxr-x---`。

---

```bash
[root@dpeak ~]# chmod 750 /var/www/html/
[root@dpeak ~]# ls -ld /var/www/html/
drwxr-x---. 2 www-data web_dev 6 Aug 26 18:37 /var/www/html/
```

---

### 9：调整权限以支持外部访问（字符模式）

- **任务描述**：由于业务需求变更，现在需要允许其他用户（如测试人员）也能读取该目录的内容。请使用字符模式（如 `o+r`）为其他人添加读取和执行权限。
- **验证标准**：使用 `ls -ld /var/www/html` 确认权限已更新，其他人获得了读取权限。

------

```bash
[root@dpeak ~]# chmod o+rx /var/www/html/
[root@dpeak ~]# ls -ld /var/www/html/
drwxr-xr-x. 2 www-data web_dev 6 Aug 26 18:37 /var/www/html/
```

## 第三阶段：团队协作与安全防护配置

### 10：配置组协作权限（SGID）

- **任务描述**：为了让 `alice` 和 `bob` 能在 `/var/www/html` 目录下无缝协作，避免每次创建文件都需要手动修改所属组。请为该目录设置 SGID 特殊权限，确保他们在此目录下创建的任何新文件，其所属组都会自动继承为 `web_dev`。
- **验证标准**：切换到 `alice` 用户，在 `/var/www/html` 下使用 `touch test.txt` 创建一个文件，然后使用 `ls -l` 查看该文件的所属组是否为 `web_dev`。

---

```bash
[root@dpeak ~]# chmod o+x /var/www
[root@dpeak ~]# chmod g+w /var/www/html/

[root@dpeak ~]# chmod g+s /var/www/html/
[root@dpeak ~]# su - alice
[alice@dpeak ~]$ touch  /var/www/html/test.txt
[alice@dpeak ~]$ ls -l
total 0
-rw-r--r--. 1 alice web_dev 0 Aug 26 19:20 test.txt
```

### 11：配置公共上传目录防误删保护（Sticky Bit）

- **任务描述**：公司有一个公共的临时文件上传目录 `/tmp/shared_uploads`，所有人都需要往里面上传文件。为了防止开发人员手滑删掉别人上传的重要文件，请赋予该目录 777 权限，并设置粘滞位（Sticky Bit）。
- **验证标准**：使用 `ls -ld /tmp/shared_uploads` 确认权限字符串末尾带有 `t`。

---

```bash
[root@dpeak ~]# mkdir /tmp/shared_uploads
[root@dpeak ~]# chmod 1777 /tmp/shared_uploads
[root@dpeak ~]# ls -ld /tmp/shared_uploads
drwxrwxrwt. 2 root root 6 Aug 26 19:41 /tmp/shared_uploads
```

---

### 12：验证粘滞位防护效果

- **任务描述**：安全策略配置后必须进行交叉验证。请切换到 `alice` 用户在 `/tmp/shared_uploads` 目录下创建一个文件 `alice.txt`。然后切换到 `bob` 用户，尝试使用 `rm` 命令删除 `alice.txt`，观察系统是否拒绝该操作。
- **验证标准**：`bob` 用户执行删除命令时，系统应提示“Operation not permitted”或类似拒绝信息。

---

```bash
[root@dpeak ~]# su - alice
[alice@dpeak ~]$ cd /tmp/shared_uploads/
[alice@dpeak shared_uploads]$ touch alice.txt
[alice@dpeak shared_uploads]$ su - bob
Password:
[bob@dpeak ~]$ rm -f /tmp/shared_uploads/alice.txt
rm: cannot remove '/tmp/shared_uploads/alice.txt': Operation not permitted
```

---

### 13：递归修改项目子目录权限

- **任务描述**：项目上线前，发现 `/var/www/html` 目录下新建的子目录权限混乱。请使用 `chmod` 命令的递归选项，将该目录下所有内容的权限统一修改为：所有者可读可写可执行，所属组可读可执行，其他人可读可执行。
- **验证标准**：使用 `ls -lR /var/www/html` 确认所有子文件和目录权限均已更新为 `755`。

------

```bash
[root@dpeak ~]# chmod 755 -R /var/www/html/
[root@dpeak ~]# ls -lR /var/www/html/
total 0
-rwxr-xr-x. 1 alice web_dev 0 Aug 26 19:20 test.txt
```

## 第四阶段：Sudo 提权与密码安全策略

### 14：授予团队负责人创建账号权限

- **任务描述**：为了方便团队负责人 `alice` 协助管理测试账号，需要为其配置特定的 sudo 权限。请编辑 sudoers 配置，允许 `alice` 用户能够以 root 身份执行 `useradd` 命令。
- **验证标准**：切换到 `alice` 用户，使用 `sudo useradd test_user` 命令，验证是否能成功创建新用户。

---

```bash
[root@dpeak ~]# vim /etc/sudoers
alice   ALL=(root)      /usr/sbin/useradd
[root@dpeak ~]# su - alice
[alice@dpeak ~]$ sudo useradd test_user
[sudo] password for alice:
[alice@dpeak ~]$ id test_user
uid=3011(test_user) gid=3011(test_user) groups=3011(test_user)
```

---

### 15：授予临时文件清理权限

- **任务描述**：运维主管需要让 `bob` 能够清理指定的临时日志文件，但不能执行其他危险操作。请配置 sudo 权限，允许 `bob` 用户仅能执行 `rm` 命令来删除文件。
- **验证标准**：切换到 `bob` 用户，尝试使用 `sudo rm` 命令删除一个测试文件，确认操作成功；再尝试执行 `sudo ls`，确认操作被拒绝。

---

```bash
[root@dpeak ~]# vim /etc/sudoers
bob     ALL=(ALL)       /usr/bin/rm
[root@dpeak ~]# su - bob
[bob@dpeak ~]$ touch test
[bob@dpeak ~]$ sudo rm -f test
[sudo] password for bob:
[bob@dpeak ~]$ sudo ls
Sorry, user bob is not allowed to execute '/bin/ls' as root on dpeak.
```

---

### 16：以特定用户身份排查问题

- **任务描述**：你当前使用的是 `root` 账号，但需要模拟 `alice` 用户的真实环境来排查家目录的权限问题。请使用 `sudo` 命令，以 `alice` 的身份在其家目录下创建一个名为 `debug.log` 的空文件。
- **验证标准**：使用 `ls -l /home/alice/debug.log` 确认该文件的所有者为 `alice`。

---

```bash
[root@dpeak ~]# sudo -u alice touch ~alice/debug.log
[root@dpeak ~]# ls -l /home/alice/debug.log
-rw-r--r--. 1 alice web_dev 0 Aug 26 20:07 /home/alice/debug.log
```

### 17：设置密码定期强制更换策略

- **任务描述**：为了符合公司的安全合规要求，需要使用 `chage` 命令为 `bob` 设置密码策略：密码最长有效期为 `60` 天，并在密码过期前 `7` 天开始提醒用户修改。
- **验证标准**：使用 `chage -l bob` 命令查看其密码策略是否生效。

------

```bash
[root@dpeak ~]# chage bob -M 60 -W 7
[root@dpeak ~]# chage -l bob
Last password change                                    : Aug 26, 2026
Password expires                                        : Oct 25, 2026
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change          : 0
Maximum number of days between password change          : 60
Number of days of warning before password expires       : 7
```
