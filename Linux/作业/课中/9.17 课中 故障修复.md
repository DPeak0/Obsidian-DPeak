# grub.cfg引导配置文件丢失

- 模拟故障
  ```bash
  [root@dpeak ~]# rm -f /boot/grub2/grub.cfg
  
  #重启
  [root@dpeak ~]# reboot
  ```
- 找到boot分区与根分区
![](https://oss.bwihz.cn/%20PicGo/20260917113424392.png)
- 指定boot分区
  ```bash
  grub> set root=(hd0.msdos2)
  ```
  ![](https://oss.bwihz.cn/%20PicGo/20260917113621233.png)
- 指定内核文件+真正的根文件系统
```bash
grub> linux /vmlinuz-4.18.0-305.3.1.e18_4.x86_64 root=/dev/sda2
```
  ![](https://oss.bwihz.cn/%20PicGo/20260917113650006.png)
- 指定initramfs文件
```bash
grub> initrd /initramfs-4.18.0-305.3.1.e18_4.x86_64.img
```
  ![](https://oss.bwihz.cn/%20PicGo/20260917113750956.png)
- 继续引导
```bash
grub> boot
```
  ![](https://oss.bwihz.cn/%20PicGo/20260917113817023.png)
- 进入系统后重新生成grub.cfg文件
```bash
[root@dpeak ~]# grub2-mkconfig -o /boot/grub2/grub.cfg
Generating grub configuration file ...
done

```
- 重启验证,可以正常引导进入系统
  ```bash
  [root@dpeak ~]# reboot

  ```

# /boot分区文件全部丢失
在系统上执行rm-rf /boot/*模拟boot分区文件全部丢失，请你修复
截图你安装包和修复的命令。以及最终进入系统的图片
- 模拟故障
```bash
[root@dpeak ~]# rm -rf /boot/*

```
![](https://oss.bwihz.cn/%20PicGo/20260917154901818.png)
- 进入bios将光盘设置为第一启动项
  ![](https://oss.bwihz.cn/%20PicGo/20260917154942774.png)

- 第一步：重新安装kernel-core来得到vmlinuz和initramfs等文件
![](https://oss.bwihz.cn/%20PicGo/20260917160802473.png)

- 第二步：生成/boot/grub2目录，未来grub.cfg引导配置文件需要存放到这个目录下，而且grub2引导程序也会调用这个目录下的一些文件
  ```bash
  bash-4.4# grub2-install /dev/sda
  ```
  ![](https://oss.bwihz.cn/%20PicGo/20260917161920327.png)
- 第三步：重新生成/boot/grub2/grub.cfg引导配置文件
  ```bash
  bash-4.4# grub2-mkconfig -o /boot/grub2/grub.cfg
  ```
  ![](https://oss.bwihz.cn/%20PicGo/20260917162034399.png)
- exit退出，将启动项改回硬盘为第一启动项，重启即可
