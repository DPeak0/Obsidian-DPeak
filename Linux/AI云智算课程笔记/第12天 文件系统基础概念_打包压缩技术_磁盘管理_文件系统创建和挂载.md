# 文件系统
## 基础概念

- 文件只能存储在文件系统上，而文件系统构建在块设备上。
![](https://oss.bwihz.cn/PicGo/20260912221011567.png)
- 块设备：磁盘、U盘、外接硬盘、分区等。
- 格式化：创建文件系统。新文件系统会覆盖旧文件系统，所以多次格式化会导致原有数据丢失。
- 挂载：将文件系统和某个目录关联起来，必须挂载到挂载点才能访问。
- 挂载点：本质是一个目录，是文件系统的访问入口。
- 分区：对物理存储空间划分逻辑上的存储空间，类似 Windows 的 C 盘、D 盘。
## 磁盘设备命名规则
| 磁盘类型         | 命名格式            | 示例                                                |
| ------------ | --------------- | ------------------------------------------------- |
| IDE 磁盘       | /dev/hdx        | `/dev/hda`、`/dev/hdb`、`/dev/hdc`                  |
| SCSI/SATA 磁盘 | /dev/sdx        | `/dev/sda`、`/dev/sdb`、`/dev/sdc`                  |
| NVME 磁盘      | /dev/nvme0nx    | `/dev/nvme0n1`、`/dev/nvme0n2`                     |
| KVM 虚拟磁盘     | /dev/vdx        | `/dev/vda`、`/dev/vdb`、`/dev/vdc`                  |
| XEN 虚拟磁盘     | /dev/xvdx       | `/dev/xvda`、`/dev/xvdb`                           |
| LVM 设备       | /dev/mapper/xxx | `/dev/mapper/rhel-root`、`/dev/mapper/centos-root` |
>想使用磁盘存储空间，需要在磁盘设备上创建文件系统
>Linux系统开机无法启动时，可在救援模式下修复系统


## 文件系统类型
### 本地文件系统
文件系统是保存到系统本地的，只有本机才能访问这个文件系统中的文件
- Windows：`NTFS`
- Linux：`XFS`、`ext4/ext3/ext2`
	主流的Linux默认本地文件系统类型要么是XFS要么是ext4
### 网络文件系统
通过网络的方式将文件远程存储到文件系统中
- `CIFS`：Windows 与 Windows、Windows 与 Linux 之间共享。
- `NFS`：Linux 与 Linux、Linux 与 Unix 之间共享。

### 光盘文件系统
光盘设备的文件系统
- `ISO9660`
## 文件系统的组成
**文件系统主要由两部分组成：`inode`和`block`**
### inode：保存文件的元数据信息
- 文件权限
- 文件大小
- 文件时间戳
- 文件指针：指向数据块 block 的位置
### block：真正存储文件数据的位置
>系统上每个文件创建后，文件系统都会分配一个 inode。

查看 inode：
```bash
[root@servera ~]# ls -li /etc/passwd 
18169735 -rw-r--r--. 1 root root 1961 Sep  9 04:14 /etc/passwd

### 18169735 就是该文件的 inode 编号
```

## rm\cp\mv和inode关系

### `cp` 与 inode
`cp` 拷贝时：
- 文件系统重新分配一个新的 inode 编号。
- 底层会开辟一个和源文件同等大小的 block。
- 属于重新创建一份文件
### `mv` 与 inode
- 不同文件系统中移动：速度较慢
	因为真的会把 block 数据写入到新的文件系统。
- 相同文件系统中移动：速度很快
	仅仅修改了映射关系，本质上 inode 没有变化，block 也没有变化。
### `rm` 与 inode
`rm` 其实不是真正删除文件数据，而是删除文件名和 inode 的映射关系
- 系统不认识文件名，只认识 inode。
- 目录文件的数据中保存了文件名和 inode 的映射关系。
- `rm` 删除的是这个映射关系，并没有立即把文件数据从 block 中抹掉。
因此，删除文件后有可能恢复，前提是：
- 删除后该文件系统没有新的文件产生。
- 原 inode 和 block 没有被重新分配和覆盖

查看目录真正的大小一定要使用`du -sh`去查看，`ls -lhd` 查看的只是目录文件下保存inode和文件名映射关系的大小，不是目录下所有内容的总大小
```Bash
[root@localhost ~]# du -sh /etc/
29M  /etc/
```

# 打包和压缩
Windows 上的压缩包通常是“打包 + 压缩”的结合。
- **压缩**：将文件大小变小，减少存储空间。压缩只能对文件压缩，不能直接对目录压缩。
- **打包**：将一个或多个文件打包成一个包文件。打包后文件会保留属性信息，方便传输和压缩。
包文件通常以 `.tar` 结尾，表示归档文件。

# 磁盘管理
## 分区方案介绍
使用分区工具对磁盘划分分区时，必须选择一种分区方案


### MBR 分区方案
![1789227942883_d.png](https://oss.bwihz.cn/PicGo/20260912234610232.png)
- 最多支持 4 个主分区或者 3 个主分区 + 1 个扩展分区 + n 个逻辑分区
- 分区表信息位于磁盘前 512 字节中
- 单个分区大小不能超过 2TB
### GPT 分区方案
- 没有分区数量上限，最多支持 128 个分区（受系统限制）
- 单个分区可以超过 2TB，但不能超过 8ZB
- 分区表信息在磁盘头部和尾部都有。
## 分区工具的使用
- `lsblk` 查看块设备
```bash
[root@localhost ~]# lsblk 
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda      8:0    0   50G  0 disk 
├─sda1   8:1    0  512M  0 part /boot
├─sda2   8:2    0    2G  0 part [SWAP]
└─sda3   8:3    0 47.5G  0 part /
sr0     11:0    1  9.2G  0 rom  /run/media/root/Rocky-8-4-x86_64-dvd
```
- 清空磁盘的所有分区表信息和分区方案
```bash
[root@localhost ~]# dd if=/dev/zero of=/dev/sdb bs=666 count=1
```
