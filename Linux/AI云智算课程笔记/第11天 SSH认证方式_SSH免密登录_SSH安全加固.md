## SSH 简介
SSH（Secure Shell），是一个协议，也是一个工具（命令）。
**作用：** 远程登录系统或者远程传输文件。
SSH 来自于套件 **openssh**，分为：
- openssh-server（服务端）
- openssh-client（客户端）
因此 SSH 属于 **C/S 架构**（Client/Server）。
![](https://oss.bwihz.cn/%20PicGo/20260909190528296.png)
- Windows 通过 ssh 命令登录到 Linux → Windows 是客户端，Linux 是服务端
- Linux 发行版自带 openssh-server 和 openssh-client，既是服务端也是客户端
- 被别人登录时 → 服务端
- 主动登录其他主机时 → 客户端
## SSH 使用方式
- 远程登录主机
```bash
ssh 远程主机用户名@远程主机IP地址/主机名/域名
```
- 远程执行命令（不登录，只执行）
```bash
ssh 远程主机用户名@远程主机IP地址/主机名/域名 '命令'
```

**Windows 登录 Linux 的方式**
	1. 打开 cmd，输入 ssh 登录指令
	2. 下载第三方 SSH 工具：PuTTY、MobaXterm、Xshell、FinalShell 等
## scp/sftp/rsync 传输文件
openssh-client 提供了 ssh 工具，也提供了文件传输工具 **scp**。
### `scp` 
**从对端主机下载文件到本地：**
scp 远程主机用户@远程主机IP地址:远程主机文件 本机路径
**把本机文件推送到对端主机：**
scp 本机路径 远程主机用户@远程主机IP地址:远程主机文件
**常用选项：**
- `-P`：指定连接端口号，默认 22
- `-r`：拷贝目录
> **注意：** 目前不建议使用 scp，因为如果主机变量文件中存在输出命令，文件拷贝时会失败。
### `rsync`
rsync 可实现文件的上传和下载，功能与 scp 相同，但 rsync 支持 **增量同步**。
- **全量同步：** 文件大小原封不动拷贝
- **增量同步：** 只拷贝差异性数据
**首次拷贝：** 无论 scp 还是 rsync 都是全量同步。后续同步建议使用 rsync，效率更高。

| 特性               | scp | rsync      |
| ---------------- | --- | ---------- |
| 传输中断后对端是否存在不完整文件 | 是   | 否（同步成功才存在） |
| 断点续传             | 不支持 | 支持         |
| 增量同步             | 不支持 | 支持         |

**简单文件传输：** scp 或 rsync 均可。
**物理服务器数据备份：** 推荐 rsync，将业务服务器数据备份到专门的备份服务器。

- **示例**
**上传文件：**
```bash
# 将 xym 主机的 /etc/passwd 同步到 lab0 主机的 /opt 目录  
rsync -v /etc/passwd root@192.168.200.129:/opt
```
**下载文件：**
```bash
#将 lab0 主机的 /etc/group 同步到本机 /opt 目录  
rsync -v root@192.168.200.129:/etc/group /opt
```

- **rsync 目录传输规则**
	- 目录路径带 `/`：将目录下的**所有内容**同步
	- 目录路径不带 `/`：将**整个目录**同步
	```bash
	rsync -r /etc root@192.168.200.129:/opt   # 同步整个 etc 目录  
	rsync -r /etc/ root@192.168.200.129:/opt  # 同步 etc 目录下的所有文件
	```
#### 常用选项

| 选项                      | 说明                               |     |
| ----------------------- | -------------------------------- | --- |
| `-a`                    | 归档模式，拷贝目录并保留文件属性（等同于 `-rlptgoD`） |     |
| `-v`                    | 显示详细信息                           |     |
| `-z`                    | 开启压缩传输，提高效率                      |     |
| `--delete`              | 以源路径为主，删除目标路径多出的文件，保证数据一致性       |     |
| `--existing`            | 仅同步目标端已存在的文件，不存在的不同步             |     |
| `--ignore-existing`     | 仅同步不存在的文件，已存在的不更新                |     |
| `--remove-source-files` | 传输成功后删除本端源文件（跨主机 mv 移动）          |     |
|                         |                                  |     |
> **常用组合：** `-avz`（归档 + 详细 + 压缩）

## SSH 认证方式
1. 基于密码的认证（默认）
2. 基于密钥的认证（免密认证）
### 对称加密与非对称加密
SSH 加密传输数据包，即使被截获也无法得知密码内容。
#### 对称加密
加密和解密使用**同一把密钥**。
1. A 主机发起连接请求，需要验证 B 主机的用户密码  
2. A 主机输入密码，使用本机密钥文件对明文密码加密，发送给 B 主机  
3. B 主机接收加密后的密码，使用同一把密钥文件解密  
   （密钥文件来源：scp 传输或物理拷贝）  
4. B 主机将解密后的密码与本机用户密码比对
#### 非对称加密
加密使用 **公钥**，解密使用 **私钥**。
1. A 主机通过 ssh 向 B 主机发送连接请求  
   → A 主机弹出提示：是否输入 yes？  
   → 输入 yes 后，B 主机的主机公钥保存到 A 主机的 ~/.ssh/known_hosts  
2. 输入对端主机连接用户的密码  
3. A 主机使用保存的主机公钥对用户密码加密  
4. A 主机将加密后的密码发送给 B 主机  
5. B 主机使用本机 /etc/ssh 下的主机私钥解密  
6. B 主机将解密后的密码与 A 主机要登录的用户密码比对，成功则允许登录
> `/etc/ssh/` 目录下存放各主机的公钥和私钥文件。
### 基于密码的认证（默认）
连接流程如上文非对称加密流程所述。
### 基于密钥的认证（免密登录）
> **生产环境：** 通常关闭密码认证，仅允许密钥认证，安全性更高。

**前提：** 客户端需要生成一对用户公钥和私钥文件。
**需求示例：** A 主机免密登录到 B 主机的 devops 用户。
> **核心原则：** 想免密登录谁，就把用户公钥文件发给谁。

**A 主机操作：**
```bash
# 第 1 步：手动生成公钥和私钥  
ssh-keygen  

# 第 2 步：将用户公钥发送到服务端指定用户  
ssh-copy-id -i /root/.ssh/id_rsa.pub devops@192.168.200.130
```
免密配置完成后，即可直接登录。
### 私钥文件加密
私钥泄露 → 他人可免密登录。给私钥文件加密后，使用私钥时需验证密码。

## SSH 配置文件
```bash
/etc/ssh/  
├── ssh_config          # 客户端配置  
├── ssh_config.d/  
├── sshd_config         # 服务端配置（重点）  
├── moduli  
├── ssh_host_ecdsa_key        # 主机私钥  
├── ssh_host_ecdsa_key.pub    # 主机公钥  
├── ssh_host_ed25519_key  
├── ssh_host_ed25519_key.pub  
├── ssh_host_rsa_key  
└── ssh_host_rsa_key.pub
```
> 无论学习还是生产，核心配置文件都是 **sshd_config**（服务端）。
### sshd_config 关键配置项

| 配置项                      | 说明                                 |
| ------------------------ | ---------------------------------- |
| `Port`                   | sshd 监听端口                          |
| `ListenAddress`          | 监听的 IP 地址，`0.0.0.0` 表示监听所有 IPv4 地址 |
| `PermitRootLogin`        | 是否允许 root 远程 SSH 登录（生产环境应关闭）       |
| `MaxAuthTries`           | 密码失败后重试次数（生产环境应调小）                 |
| `PubkeyAuthentication`   | 是否开启密钥认证                           |
| `PasswordAuthentication` | 是否开启密码认证                           |
| `PermitEmptyPasswords`   | 是否允许空密码认证                          |
### 黑白名单

**黑名单（拒绝登录）：**
```bash
DenyUsers user@*                     # 禁止任何人登录 user 用户  
DenyUsers user@192.168.200.100       # 禁止该 IP 登录 user  
DenyUsers user@192.168.200.0/24      # 禁止该子网所有 IP 登录  
DenyUsers *@192.168.200.100          # 禁止该 IP 登录任何用户  
DenyUsers *@*                        # 禁止所有来源所有用户
```
**白名单（仅允许登录）：**
```bash
AllowUsers user@*                    # 仅允许 user 用户登录
```

## SSH 隧道网络（端口转发）

### 本地端口转发

将本地的某个端口流量转发到本地的另外一个端口上。
**场景：** 主机无法直接访问另一台主机的服务（防火墙阻挡外部流量进入 80 端口），借助本地端口转发通过 SSH 通道实现访问。

原来：客户端 → 服务端 80 端口（被防火墙阻挡）  
现在：客户端 → 服务端 SSH 22 端口（建立通道） → 转发到 80 端口
### 远程端口转发
将远程主机的端口转发到本机的某个端口，让本机的服务对外暴露。
ssh -R 远程开放的端口:本地IP地址:本地端口 远程主机用户@远程主机IP地址
