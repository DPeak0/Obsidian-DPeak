# 8.26 用户管理和权限管理

## 用户管理

### 1.用户的作用

- **身份验证与登录**：通过用户账户登录系统，实现身份识别。
- **进程运行者**：系统上所有程序（进程）都需要依附于一个用户身份来运行。
- **权限管控**：通过用户归属和权限设置，实现文件和资源的访问隔离与控制。

### 2.用户的分类

系统是根据用户的ID来区分它是属于哪类用户的—>用户ID，称之为**UID**

| 用户类别       | UID范围     | 特点与用途                                                   |
| -------------- | ----------- | ------------------------------------------------------------ |
| **超级管理员** | **0**       | 即`root`用户，拥有系统最高权限，可执行任何操作               |
| **系统用户**   | **1 ~ 999** | 通常无法登录系统，主要用于后台运行服务或守护进程（如nginx、mysql） |
| **普通用户**   | **≥ 1000**  | 这类用户都是给人使用的，由管理员手动创建。                   |

### /etc/passwd	 用户信息文件  

```bash
name:password:UID:GID:GECOS:directory:shell
```

name：用户名称
password：密码占位符（如果有x说明基于这个用户登录系统需要经过用户密码验证，如果没有x说明基于这个用户登录系统不需要密码验证）
UID：用户的UID，用户名和UID映射关系这里来的
GID：用户组的ID GECOS：用户的描述信息-->最终会在图形化的登录页面上展现出来 
directory：用户登录系统后默认所在的目录（家目录） 
shell：用户登录系统执行的第一个命令
  /bin/bash：用户可以登录系统获取终端来执行命令（用户可以登录系统）
  /sbin/nologin：用户不可以登录系统

### 管理用户的命令

#### 创建用户：useradd

创建用户的时候，如果没有指定UID是多少，系统会自动分配UID给它

useradd创建用户的时候，它的所有的选项都是为了/etc/passwd服务的，所以/etc/passwd文件中这些字段有哪些作用，useradd命令创建的时候就可以通过选项指定它

```bash
-u：指定UID
-d：指定家目录
-m：如果家目录不存在，则自动创建
-M：不创建家目录
-s：指定用户登录后的命令行解释器
-c：用户描述信息
-g：指定主组
-G：指定附加组
-e：设置账户失效日期
-f：密码过期后多少天账户被永久禁用（-1表示永不，0表示立即）
-r：创建一个系统用户（用于运行服务/守护进程）。且默认不创建家目录。
```



#### 删除用户：userdel

一个用户创建完成之后，系统上会多出以下的文件：

  /home/username：用户的家目录

  /var/spool/mail/username：用户的邮箱文件

```bash
-r：同时删除用户家目录和邮箱
```



#### 修改用户信息：usermod

```bash
-c：修改备注
-d：修改家目录
-m：必须与 -d 配合使用，将原家目录内容物理移动到新路径
-s：修改用户登录后的命令行解释器
-u：修改UID
-g：修改主组
-G：修改附加组
-a：追加模式，如-aG表示追加到附加组
-l：修改用户名
```

#### passwd-修改用户密码

- root用户修改密码
    - 修改密码的时候需要经过原有用户密码的验证么？：不需要
    - 是否能够修改其他用户的密码？：可以
    - 修改密码的时候是否需要遵循密码策略？：不需要
- 普通用户修改密码
    - 给自己修改密码的时候，passwd命令后面不能接上用户名
    - 普通用户修改密码要不要验证原有密码？：需要
    - 是否可以修改其他用户密码？：不可以
    - 修改密码的时候是否需要遵循密码策略？：需要

```bash
--stdin：非交互式修改密码
-l：锁定用户密码
-u：解锁被锁定的用户密码
-d：删除用户密码
-e：立即是密码过期
-n：设置密码最短有效天数
-x：设置密码最长有效天数
-w：密码过期前多少天开始警告用户
-i：密码过期后，账户被彻底禁用前的宽限天数
-S：显示账户密码状态，与-a同用显示所有账户的密码状态
```



### 用户组作用

- **定义**：用户组（Group）是**多个用户的集合**。
- **核心作用**：方便权限管理。通过将用户加入组，可以批量赋予或收回权限，无需逐个用户设置。

### 用户组的分类

- 私有组（属主）：
    - 用户必须要加入一个组中，这个组就是它的私有组
    - 系统上，每一次创建新的普通用户的时候，会同时创建一个和用户名同名的组，作为这个用户的私有组
- 附加组：
    - 一个用户可以有0个或多个附加组
    - 除了自己的私有组之外，用户还可以加入到其他的组里面，那么其他的组就是这个用户的附加组

**为什么用户要加入到附加组中？**

答：为了获取到这个组的权限

### /etc/group 	用户组信息文件

```bash
group_name:password:GID:user_list
```

group_name：组的名字

password：组的密码占位符，表示登录这个组是否需要密码验证（如果是x表示需要验证，如果没有x表示不需要密码验证）组是可以被登录的

GID：组的ID，gid

user_list：组内的成员（如果这个组是用户的附加组，那么这里会看到成员）

### /etc/gshadow 	用户组密码文件

```bash
group_name:::
```

第一列：组的名字 

第二列：组加密后的密码，采用的sha512方式 

第三列：组的管理员（管理员可以修改组的密码，并且管理组的成员-添加用户到组，删除组的成员） 

第四列：组的成员  

### 管理用户组的命令

#### 创建组：groupadd

```bash
groupadd [选项] 组名
    -g：指定GID
    -f：强制/不报错，如果组已存在，不报错并直接成功退出；若配合 -g 且GID被占用，会分配一个新GID。
    -p：设置密码（不能写明文）
```

#### 删除组：groupdel

```bash
groupdel [选项] 组名
    -f：强制删除
```

#### 修改组：groupmod

```bash
groupmod [选项] 组名
    -n：重命名
    -g：修改GID
    -p：修改密码（不能写明文）
```

#### groupmems 单纯的管理组的成员

```bash
groupmems [选项] [动作]
    ● 选项：
    -g groupname：指定要更改的组
    -R CHROOT_DIR：在指定的 chroot 目录下应用更改，仅支持绝对路径
    ● 动作：
    -a：添加用户到组成员列表
    -d：将用户从组成员列表中删除
    -p：清空组的所有成员
    -l：列出当前组的所有成员
```

#### gpasswd

- 设置组的管理员
- 设置组的密码
- 管理组的成员：添加组的成员/删除组的成员

```bash
gpasswd [选项] 组
    -a user：添加用户到指定的组中
    -d：删除某个组成员
    -Q CHROOT_DIR：在指定的 chroot 目录下应用更改，仅支持绝对路径
    -r：删除组密码
    -R：限制组的访问（将组密码设为 !）
    -M USER,...：设置组成员（会覆盖当前组成员）
    -A：设置组管理员
```

## 权限管理

#### 权限的作用

- **核心目的**：保障系统安全，实现资源隔离。
- **具体体现**：
  - 没有权限控制 → 任何用户都能访问/修改任意文件（混乱且危险）
  - 有权限控制 → 用户和进程只能访问被授权的文件和目录

#### 三大基本权限（RWX）

| 权限     | 字母 | 数字（八进制） | 含义                                    |
| :------- | :--- | :------------- | :-------------------------------------- |
| **读**   | `r`  | 4              | 查看文件内容 / 列出目录内容             |
| **写**   | `w`  | 2              | 编辑文件内容 / 创建或删除目录下的文件   |
| **执行** | `x`  | 1              | 执行文件（命令/脚本）/ 进入目录（`cd`） |

**文件权限的匹配顺序**：先看是不是文件的**拥有人**，再看你是不是在文件的**拥有组**中，最后看**其他人**的权限

#### 特殊权限

`SUID`：u+s（4---），如果在一个可执行命令上添加了SUID权限后，那么任何人在执行该命令时会临时得到该命令拥有人的权限
`SGID`：g+s（2---），如果在一个可执行命令上添加了SGID权限后，那么任何人在执行该命令时会临时得到该命令拥有组的权限
`SBIT（sticky冒险位）`：o+t（1---），如果在一个目录上添加了sticky权限，那么任何人在该目录下创建的文件，仅root和该文件拥有人可以删除，一般设置为1777

#### umask权限掩码

目录文件的默认权限=777-umask

 777-022=755

普通文件的默认权限=666-umask （如果普通文件创建出来，带有x权限的话，会自动+1）

 666-022=644

如果目录文件和普通文件计算的umask值不一样，要以目录文件计算的umask值为主

#### chmod-修改文件权限

- 基于字符方式（rwx）修改

```text
chmod 操作对象|操作属性符|权限 文件
  操作对象：
    u
    g
    o
    a
  操作属性符：
    +
    -
    = （直接赋予权限，会覆盖原有的权限）
  权限：
    r
    w
    x
```

- 基于数字方式修改

第一个数字：拥有人的权限

第二个数字：拥有组的权限

第三个数字：其他人的权限

```Bash
chmod 644 /etc/passwd
chmod 777 /etc/passwd
chmod 000 /etc/passwd
chmod 555 /etc/passwd

4：r权限
2：w权限
1：x权限
```
- 选项

```bash
	-R：递归修改
    -c：仅在发生实际更改时显示详细信息
    -v：显示操作详细
    -f：忽略大部分错误信息
```

#### chown：修改文件的拥有人/拥有组

```bash
chown 拥有人:拥有组 [选项] 文件
    -R：递归修改
    -c：仅在发生实际更改时显示详细信息
    -v：显示操作详细
    -f：忽略大部分错误信息
```
