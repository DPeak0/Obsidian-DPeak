#### 正则表达式
grep命令本身支持很多方式的过滤，但是如果要求你过滤以root关键字开头的行，grep本身无法实现，需要借助正则表达式的元字符来实现

```Bash
[root@xym ~]# grep ^root /etc/passwd 
root:x:0:0:root:/root:/bin/bash

```

- 基本正则表达式
- 扩展正则表达式
- 区别在于：扩展正则表达式支持的元字符更多

**所谓的正则表达式，就是通过不同的元字符实现不同规律的过滤**

下面是基本正则表达式的元字符
- ^：以某关键字开头的
```Bash
grep ^memeda /etc/passwd 
```

# 进程管理
## `ps`：静态查看进程
### 选项：
- `-e` 或 `-A`：查看所有进程
- `-a`：查看所有终端上的进程
- `-ef`：查看所有的进程，还能查看到父进程（PPID）信息
- `-aux`：cpu的占比、内存的占比、虚拟内存、实际内存、进程的状态
	- `a`（显示所有终端进程，包括其他用户）
	- `x`（显示没有终端的进程，如守护进程）
	- `u`（以用户易读的格式显示，增加CPU/内存占用率）。
- `--sort=`：根据资源消耗进行排序
	- 如：`ps -aux --sort=%cpu` 升序排序 
		- `ps -axu --sort=-%cpu` 倒叙排序
- `-o`：通过指定格式输出
	- 如：`ps -axo user,pid,ppid,%cpu,%mem,command`

- **示例**：
```bash
[root@dpeak ~]# ps
    PID TTY          TIME CMD
  22841 pts/0    00:00:00 bash
  26949 pts/0    00:00:00 ps
  
###TIME ：进程消耗的CPU时间分片-->值越大，说明消耗的CPU越多
```

### 选项

### 说明![](https://oss.bwihz.cn/%20PicGo/20260907194814911.png)
```text
%Cpu(s):  1.8 us,  1.2 sy,  0.0 ni, 96.5 id,  0.0 wa,  0.5 hi,  0.0 si,  0.0 st
```
**us**：user用户空间（用户态）消耗的CPU资源百分比-->应用软件消耗的CPU资源
**sy**：system内核空间（内核态）消耗的CPU资源百分比
**ni**：nice（进程的优先级）调整过ni值进程消耗CPU资源百分之（CPU计算进程的nice）
**id**：CPU资源空闲百分比
**wa**：wait等待，CPU等待磁盘IO时间百分比
	计算机硬件中，CPU处理效率最高，最低的就是磁盘
**hi**：硬中断，硬中断消耗CPU时间百分比
	键盘上按下一个按键，这个时候CPU会优先处理按键的操作
	网卡，如果网卡接受到大量的数据包
	这个值如果拉高，大概率说明你当前的系统处于一个高并发场景，有很多的人同时发送数据包给你的主机
**si**：软中断，队列中等待的时间
	浏览器+网卡接收到了很多数据包
	如果没有si的话，那么CPU会把所有的数据包处理完之后再去处理浏览器
	对于用户来说，你访问浏览器就会一直卡住
	如果有si的话，那么CPU会把浏览器处理的请求放到一个队列中
	一边处理数据包，一边处理浏览器的请求
	对于用户来说，浏览器可以访问，就是页面打开的比较慢
**st**：被hyperviser偷取的CPU时间（只有当你的系统是虚拟机的情况下）
	虚拟化层，有了虚拟化层才可以创建虚拟机
	值越高，那么就说明你当前的机器得到的CPU资源就越低
	说明虚拟机当前所在的宿主机CPU资源不够，或者是宿主机上其他的虚拟机分配走了CPU资源

![](https://oss.bwihz.cn/%20PicGo/20260907194814912.png)
buff和cache都是使用内存的空间，他们都可以叫做缓存：
	**buff解决的是写的慢问题**：CPU处理完数据写入到内容中，然后CPU就处理其他的人物，由内存把数据刷入到磁盘中
	**cache解决的是读的慢问题**：第一次读取文件，依旧从硬盘中读取，同时把文件数据记录到缓存中，后续读取相同的数据就走缓存读取
## `netstat`

### 选项

# 计划任务
## `at` 一次性计划任务
```bash
at [选项] 时间
```
### 常用选项
- `-l`：列出当前待执行任务
- `-d 任务号`：删除任务；还可以使用`atrm 任务号`
- `-c 任务号` ：查看任务内容
- `-f 文件`：从文件读取要执行的命令
- `-t 时间戳`：用 `[[CC]YY]MMDDhhmm[.ss]` 格式指定时
### at时间格式
- 具体时间
	- `'时:分:秒 年-月-日'`
	- `'时:分'`
- 抽象时间
	- am 11:00 表示上午十一点
	- pm 03:00 表示下午三点
	- tea time 表示16:00
### at黑白名单
- 白名单：`/etc/at.allow`
- 黑名单：`/etc/at.deny`
**黑白名单规则：**
1. 如果 `/etc/at.allow` 存在，则只有该文件中列出的用户可以使用 `at`，并且 `/etc/at.deny` 会被忽略
2. 如果 `/etc/at.allow` 不存在，则检查 `/etc/at.deny`，其中列出的用户不能使用 `at`，未列出的用户可以使用
3. 如果两个文件都不存在，通常只有 `root` 可以使用 `at`
4. 如果用户同时存在于白名单和黑名单，白名单优先级更高。也就是说：只要白名单存在，那么仅白名单生效
### 示例
```bash
at 15:30                 # 今天 15:30，如果已过则明天
at 15:30 today           # 今天 15:30
at 15:30 tomorrow        # 明天 15:30
at 3:30 PM               # 下午 3:30
at now + 10 minutes      # 10 分钟后
at now + 1 hour          # 1 小时后
at 15:30 2029-09-07      # 2029-09-07 15:30
at -t 202909071530       # 时间戳格式：2029-09-07 15:30

###在2026-09-07下午 3:30 定时执行 `rm -rf /tmp/*`
[root@memeda ~]# at '15:30 2026-09-07'
warning: commands will be executed using /bin/sh
at> rm -rf /tmp/*
at> <EOT>    # 按 Ctrl+D 保存退出
job 2 at Fri Sep  7 15:30:00 2029
```
## `crontab` 周期性计划任务
```bash
crontab [-u 用户] [-l | -r | -e] [-i] [文件]
```
### 常用选项
`-e`：编辑当前用户的计划任务
`-u 用户名`：指定用户
`-l`：列出当前用户的计划任务
`-r`：删除当前用户的全部计划任务
`-i`：删除前提示确认
### crontab时间格式
```bash
*  *  *  *  *  命令
分 时 日 月 周

分：0-59
时：0-23
日：1-31
月：1-12
周：0-7，0和7都表示周日，1-6表示周一至周六

*     表示任意值             
#示例：* * * * * 表示每分钟     00:01,00:02,00:03...
*/x   表示x个单位            
#示例：*/5 * * * * 表示每5分钟  00:05,00:10,00:15...
x-y   表示x到y               
#示例：0 9-17 * * * 表示9点到17点 09:00,10:00,...,17:00
x,y   表示x和y               
#示例：0 9,17 * * * 表示9点和17点 09:00,17:00
x-y/z 表示x到y范围内每z个单位 
#示例：0 9-17/2 * * * 表示9点到17点每2小时 9:00,11:00,...,17:00
```
### crontab 任务文件位置
- 用户级任务：`/var/spool/cron/`目录下
  使用`crontab -e`定义任务时会在该目录下生产以用户名命名的任务文件
- 系统级任务：`/etc/crontab`
  ![](https://oss.bwihz.cn/PicGo/20260912172015938.png)
- `/etc/cron.hourly`
>默认这个目录下的可执行文件才会去执行-->因为在/etc/cron.d/0hourly文件中定义了
- `/etc/cron.daily`
- `/etc/cron.monthly`
- `/etc/cron.weekly`

### crontab输出与日志
`crontab` 任务不会把输出直接打印到屏幕。
- **任务执行日志通常记录在 `/var/log/cron`**
- 命令的输出默认可能通过邮件发送给用户
- 如果不想收邮件，可以设置 `MAILTO=""`，或把输出重定向
### crontab黑白名单
- 白名单：`/etc/cron.allow`
- 黑名单：`/etc/cron.deny`
**规则：**
1. 如果 `/etc/cron.allow` 存在，只有该文件中列出的用户可以使用 `crontab`
2. 如果 `/etc/cron.allow` 不存在，则检查 `/etc/cron.deny`，其中列出的用户不能使用
3. 如果两个文件都不存在，通常只有 `root` 可以使用 `crontab`
4. 如果用户同时存在于白名单和黑名单，白名单优先级更高。也就是说：只要白名单存在，那么仅白名单生效
### 示例
```bash
# 每分钟执行
* * * * * echo "每分钟"

# 每天 9:00 执行
0 9 * * * ls

# 每 5 分钟执行
*/5 * * * * echo "每5分钟"

# 每 2 小时执行
0 */2 * * * echo "每2小时"

# 周一到周五 9 点到 17 点整点执行
0 9-17 * * 1-5 echo "工作日"

# 每月 1 日和 15 日零点执行
0 0 1,15 * * echo "每月1日和15日"

# 每周五 23:12 执行
12 23 * * 5 cp /etc/passwd /tmp/passwd-$(date +\%F)

# 特殊字符串写法
@reboot echo "开机后执行"
@daily echo "每天执行一次"
@hourly echo "每小时执行一次"
@weekly echo "每周执行一次"
@monthly echo "每月执行一次"
@yearly echo "每年执行一次"
```

>`crontab` 中 `%` 必须转义为 `\%`，否则命令会被截断
>建议命令使用绝对路径，避免 `PATH` 问题

|`ro`|只读|

|`relatime`|相对访问时间，性能较好，常见默认|

|`remount`|重新挂载，常用于修改挂载参数|

|`_netdev`|网络设备，等网络可用后再挂载|
|`nofail`|挂载失败不影响系统启动|
|`uid=、gid=`|指定挂载后文件属主、属组，常用于 vfat/ntfs|
|`umask=`|指定权限掩码，常用于 vfat/ntfs|
|`iocharset=utf8`|指定字符集|

|`noatime`|提升性能，减少写操作|
