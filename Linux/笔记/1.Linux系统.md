## 命令语法
### 命令三要素：
- **命令**：要实现的功能（useradd命令创建用户、passwd命令修改密码等）
- **选项**：对命令功能的补充，以 `-`（短格式）或 `--`（长格式）开头
- **参数**：命令操作的对象（用户名、文件名、设备名等）

### 命令书写规范：
```text
命令 选项 选项的参数 参数
```
- 命令一定在选项和参数的最前面
- 命令和选项之间使用空格隔开
- 选项和参数之间使用空格隔开
- 选项和选项之间使用空格隔开
- 参数和参数之间使用空格隔开
```bash
useradd [options] LOGIN
```
-  \[ ] ： 表示可选
- 大小字母：表示必填
- ...：表示可以接多个
- a|b|c：多选一
- < > ：表示有默认值，可以省略。如果你写了那么就是覆盖

## 用户管理
>[[1.Linux系统#用户管理|用户管理]]      [[2.Linux命令选项解析#用户管理|用户管理相关命令]]      [[3.Linux配置文件解析#用户管理|用户管理相关文件]]
### 用户的作用与分类
- **身份验证与登录**：通过用户账户登录系统，实现身份识别。
- **进程运行者**：系统上所有程序（进程）都需要依附于一个用户身份来运行。
- **权限管控**：通过用户归属和权限设置，实现文件和资源的访问隔离与控制。
- 系统是根据用户的ID来区分它是属于哪类用户的—>用户ID，称之为**UID**

| 用户类别      | UID范围       | 特点与用途                                  |
| --------- | ----------- | -------------------------------------- |
| **超级管理员** | **0**       | 即`root`用户，拥有系统最高权限，可执行任何操作             |
| **系统用户**  | **1 ~ 999** | 通常无法登录系统，主要用于后台运行服务或守护进程（如nginx、mysql） |
| **普通用户**  | **≥ 1000**  | 这类用户都是给人使用的，由管理员手动创建。                  |

### 用户组的作用与分类

- **定义**：用户组是**多个用户的集合**。
- **核心作用**：方便对用户进行**统一管理**，尤其是权限分配。
    比如：让开发组所有成员都能读写 `/project` 目录，只需将他们都加入 `dev` 组，再设置组权限即可，无需逐个用户配置。

| 类型           | 说明                          | 特点                                 |
| ------------ | --------------------------- | ---------------------------------- |
| **私有组（属主组）** | 每个用户**必须**属于一个组，这个组就是它的私有组。 | 系统创建普通用户时，**自动创建**一个同名组，作为该用户的私有组。 |
| **附加组**      | 用户除了私有组外，还可以加入的其他组。         | 一个用户可以有**多个**附加组。                  |


## 权限管理
>[[1.Linux系统#权限管理|权限管理]]     [[2.Linux命令选项解析#权限管理|权限管理相关命令]]     [[3.Linux配置文件解析#权限管理|权限管理相关文件]]
### 基本权限
- `r`（4--）：读
- `w`（-2-）：写
- `x`（--1）：执行

**文件权限的匹配顺序**：
1. 先看是不是文件的**拥有人**
2. 再看你是不是在文件的**拥有组**中
3. 最后看**其他人**的权限

### 特殊权限

`SUID`：u+s（4---），如果在一个可执行命令上添加了SUID权限后，那么任何人在执行该命令时会临时得到该命令拥有人的权限  
`SGID`：g+s（2---），如果在一个可执行命令上添加了SGID权限后，那么任何人在执行该命令时会临时得到该命令拥有组的权限  
`SBIT（sticky）`：o+t（1---），如果在一个目录上添加了sticky权限，那么任何人在该目录下创建的文件，仅root和该文件拥有人可以删除，一般设置为1777

### umask权限掩码

目录文件的默认权限=777-umask
	777-022=755

普通文件的默认权限=666-umask （如果普通文件创建出来，带有x权限的话，会自动+1）
	666-022=644

如果目录文件和普通文件计算的umask值不一样，要以目录文件计算的umask值为主
### ACL权限  
#### 1.ACL 是什么
- ACL：访问控制列表（Access Control List）
- 作用：在传统 `rwx` 权限基础上，实现更精细的权限控制。
- 核心能力：
    - 允许**指定用户**对文件拥有特定权限
    - 允许**指定用户组**对文件拥有特定权限
#### 2.权限匹配优先级
访问文件时，按以下顺序匹配（**先命中即生效**）：
1. 拥有人（owner）
2. 用户 ACL（指定用户）
3. 拥有组（group）
4. 用户组 ACL（指定组）
5. 其他人（other）
#### 3.查看 ACL 权限
![image.png](https://oss.bwihz.cn/PicGo/20260829234055643.png)
- 使用 `ls -l` 查看，若权限位末尾出现 `+`，表示该文件有 ACL 权限。
- 使用 [[2.Linux命令选项解析#getfacl：查看ACL权限|getfacl <文件>]] 查看详细的 ACL 权限列表。

#### 4.mask（权限掩码）

- **含义**：控制 ACL 权限的**有效权限**。
- **规则**：
    - 用户或组的实际权限 = 其 ACL 权限 **∩** mask 权限（按位与）。
	    例如：ACL 为 `rwx`，mask 为 `r--`，则有效权限为 `r--`。

- 文件有 ACL 后，`ls -l` 显示的**组权限位**实际是 **mask 值**。
- 使用 `chmod g+xxx` 或 `setfacl -m m::rwx` 可修改 mask。

#### 5.修改/删除 ACL 权限（[[2.Linux命令选项解析#setfacl：修改ACL权限|setfacl]]）
 - **为指定用户设置 ACL**
```bash
setfacl -m u:用户名:权限 文件
```
- **为指定用户组设置 ACL**
```bash
setfacl -m g:组名:权限 文件
```
- **修改文件本身的拥有组（不带用户/组名）**
```bash
setfacl -m g::权限 文件   # 注意双冒号
```
- **删除所有 ACL**：
```bash
setfacl -b 文件
```
- **删除指定用户的 ACL**：
```bash
setfacl -x u:用户名 文件
```
- **删除指定组的 ACL**：
```bash
setfacl -x g:组名 文件
```

#### 6.默认 ACL（继承）
- **用途**：让目录下**新创建**的文件自动继承目录的 ACL 权限。
- **设置**（在目录上）：
```bash
setfacl -m d:u:用户名:权限 目录
setfacl -m d:g:组名:权限 目录
```
- **特点**：
    - 对目录本身无效，只作用于新建的子文件/子目录。
    - 普通文件创建时不会自带 `x` 权限，因此继承后的 mask 可能自动去掉 `x`。
- **查看**：`getfacl` 中会显示 `default:` 开头的条目。
- **删除默认 ACL**：
```bash
setfacl -k 目录
```

#### 7.注意事项
- 修改文件基本权限（`chmod`）时，更改 **owner** 或 **other** 正常，更改 **group** 实际会修改 **mask**，而非原来的组权限。
- 若要修改拥有组的基本权限，应使用 `setfacl -m g::权限`。

## shell
### Shell 概述

- **Shell 的作用**：Linux 中的**命令解释器**，将用户输入的命令翻译为内核能理解的语言。没有 Shell，用户无法执行任何命令。
- **登录 Shell 程序**：用户在 `/etc/passwd` 中最后一列指定（如 `/bin/bash`），即用户登录后默认使用的 Shell。
- **执行流程**：  
    用户执行命令 → 交给 Shell → 内核
![](https://oss.bwihz.cn/%20PicGo/20260901192602949.png)
- 常见的 Shell 程序

| Shell | 说明                    |
| ----- | --------------------- |
| bash  | 主流 Shell，大多数 Linux 默认 |
| sh    | 早期 Shell，通常软链接到 bash  |
| csh   | C 语言风格的 Shell         |
| ksh   | Korn Shell            |

- **查看当前使用的 Shell**：`echo $SHELL`
```bash
[root@dpeak ~]# echo $SHELL
/bin/bash
```
- **查看系统支持的 Shell**：`cat /etc/shells`
```bash
[root@dpeak ~]# cat /etc/shells

```

## 变量

### 1. 变量基础
- 变量由 **变量名** 和 **变量值** 组成，格式：`变量名=变量值`
- 变量占用内存空间，用于存储数据。
- **命名规则**：由字母、数字、下划线组成，**不能以数字开头**。
- 多次赋值同一个变量，新值会覆盖旧值。
### 2. 变量分类
- **本地变量**
    **作用域范围：当前SHELL中**
    **定义本地变量的方式**：变量名=变量值

- **环境变量**
	**作用域范围：当前SEHLL和子SHELL中**
	**定义环境变量的方式：**`export 变量名=变量值`
	将本地变量转化为环境变量：`export 本地变量`

- 系统变量：系统的一些变量，比如说PWD、HOME、USER
    PS1：决定当前终端上的命令提示符
    **PATH**：保存的是系统上命令文件的目录
### 3. 变量操作
- **引用变量**：`$变量名` 或 `${变量名}`
- **查看所有变量**（含本地+环境）：`set`
- **查看环境变量**：`env`
- **取消变量**：`unset 变量名`
### 4. 变量的永久生效
- **全局（所有用户）**：写入 `/etc/bashrc`（每次用户登录都会加载）
- **个人（仅当前用户）**：写入 `~/.bashrc`（仅该用户登录加载）
### 5. 转义字符

| 符号         | 作用                                 |
| ---------- | ---------------------------------- |
| `\`        | 转义其后单个字符（去掉特殊意义）                   |
| `" "`（双引号） | 弱引用，保留 `$`、`` ` ``、`!` 等特殊符号的功能 \| |
| `' '`（单引号） | 强引用，引号内所有字符均失去特殊意义（原样输出）           |

- 示例：
```bash
a=100
echo "$a"   # 输出 100
echo '$a'   # 输出 $a
```

## 别名（alias）

- **作用**：为长命令定义简短的别名，提高效率。
- **定义**：`alias 别名='命令'` 或 `alias 别名="命令"`
- **查看所有别名**：`alias`
- **取消别名**：`unalias 别名`
  
示例：

```bash
alias lsnet='ls -l /etc/sysconfig/network-scripts/'
alias cpetc='cp -r /etc /tmp/etc-$(date +%F)'
```
- 要使别名永久生效，写入 `/etc/bashrc`（全局）或 `~/.bashrc`（个人）。
